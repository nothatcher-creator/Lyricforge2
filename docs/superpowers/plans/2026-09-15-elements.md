# Elements Asset Type Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add first-class installable visual Elements that can be inserted from the catalog as ordinary editable image clips and restored as project dependencies.

**Architecture:** Extend the creative/catalog type system with non-executable `element` packages carrying PNG/SVG payloads. Reuse catalog storage for package bytes, then materialize installed Element bytes into the project asset store and existing image-clip renderer on insertion. Project dependencies retain the exact element package version/source catalog for restore.

**Tech Stack:** TypeScript, Zod, React, IndexedDB/Cache Storage catalog layer, existing project asset/blob store, existing image renderer, Vitest.

**Spec:** `docs/superpowers/specs/2026-09-15-audio-aware-alignment-catalog-elements-design.md`

## Global Constraints

- `element` is additive; old projects/packages must still load.
- Element packages are non-executable and may not declare runtime IDs.
- Initial supported payloads: static SVG and PNG only.
- Installed Elements are inserted through the existing image-asset/image-clip path.
- Project dependencies record exact element id/version/source catalog.
- Ship at least 24 Elements, with at least 12 original LyricForge Elements.
